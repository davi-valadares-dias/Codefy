PARTE I — DEFINIÇÃO DO PRODUTO
1. Visão geral do Codefy
1.1. Descrição

O Codefy será uma aplicação web de portfólio profissional desenvolvida para centralizar e apresentar a trajetória de um desenvolvedor de software.

O sistema será composto por três ambientes principais:

Um site público para apresentar suas informações profissionais, projetos e competências.

Um painel administrativo privado para gerenciar todo o conteúdo.

Um módulo de análise de código, desenvolvido em C++, para extrair estatísticas técnicas de repositórios selecionados do GitHub.

O conteúdo exibido no portfólio será armazenado em banco de dados e disponibilizado por meio de uma API REST.

O administrador poderá modificar projetos, experiências, informações pessoais e outros conteúdos sem necessidade de alterar o código-fonte ou realizar um novo deploy a cada atualização.

1.2. Natureza do produto

O Codefy será um sistema de uso individual, e não um SaaS comercial multiusuário.

Não haverá:

Cadastro público de usuários.

Criação de portfólios para terceiros.

Assinaturas ou planos pagos.

Organizações ou equipes.

Múltiplos administradores.

Sistema de cobrança.

Painel para recrutadores.

A aplicação terá somente uma conta administrativa, responsável pelo gerenciamento do seu próprio portfólio.

1.3. Objetivo principal

Desenvolver um portfólio profissional dinâmico que apresente seus projetos e, simultaneamente, demonstre suas habilidades técnicas em desenvolvimento frontend, backend, banco de dados, C++, integração de sistemas, segurança e deploy.

1.4. Objetivos específicos

Apresentar sua trajetória profissional.

Organizar e divulgar projetos.

Demonstrar habilidades técnicas.

Disponibilizar informações de contato.

Integrar informações de repositórios GitHub.

Permitir administração dinâmica dos conteúdos.

Apresentar estatísticas dos projetos.

Disponibilizar currículo profissional.

Demonstrar capacidade de desenvolver e manter uma aplicação completa.

PARTE V — MÓDULO ESPECIALIZADO EM C++
18. GitHub Code Analyzer
Codefy Analyzer

Módulo desenvolvido em C++ para análise estática de repositórios.

Funcionalidade diferencial

Processamento de arquivos, identificação de linguagens, contagem de linhas e geração de estatísticas técnicas.

Esse será o módulo responsável por demonstrar a utilização de C++ no seu portfólio.

Ele funcionará independentemente da interface e da API principal.

18.1. Objetivo

Analisar arquivos de código de repositórios selecionados, extraindo métricas que poderão ser apresentadas na página individual de cada projeto.

O analisador não deverá compilar nem executar código obtido do GitHub.

Sua função será apenas examinar os arquivos.

05

O backend inicia o analisador com limites definidos.

06

Receber JSON

O analisador devolve métricas e informações do processamento.

07

Persistir resultado

O backend valida e armazena o resultado no PostgreSQL.

08

Apresentar dados

O frontend exibe as estatísticas no projeto.

Decisão técnica: snapshots

O Codefy deverá analisar uma versão identificável do repositório.

A API deverá armazenar o commit correspondente à análise, permitindo indicar quais arquivos foram utilizados.

Isso evita que o resultado seja apresentado como atual quando o repositório já recebeu novas alterações.

20. Comunicação C# → C++

A primeira versão utilizará execução de processo.

O backend C# iniciará o executável C++ e informará o diretório que deve ser analisado.

O processo retornará um documento JSON.

Contrato de saída ilustrativo:

{
  "status": "completed",
  "filesAnalyzed": 124,
  "totalLines": 8420,
  "languages": [
    {
      "name": "TypeScript",
      "files": 70,
      "lines": 4800,
      "percentage": 57.01
    },
    {
      "name": "C#",
      "files": 54,
      "lines": 3620,
      "percentage": 42.99
    }
  ]
}

Esses valores são fictícios.

O percentual deverá ser calculado utilizando a quantidade de linhas das linguagens reconhecidas como denominador.

Caso nenhuma linguagem seja reconhecida, o resultado deverá retornar uma distribuição vazia, evitando divisão por zero.

Regras da comunicação

A API deverá validar os parâmetros.

O processo terá tempo máximo de execução.

O processo terá limite de recursos.

O JSON retornado deverá ser validado.

Mensagens técnicas poderão ser registradas separadamente.

O processo não deverá receber credenciais do GitHub.

Diretórios temporários deverão ser removidos após a análise.

Erros não poderão derrubar a API principal.

21. Segurança do analisador

Esse ponto é especialmente importante porque o sistema processará arquivos obtidos externamente.

RN-011: Somente repositórios públicos do GitHub explicitamente selecionados poderão ser analisados na primeira versão.

RN-012: A API deverá validar proprietário e nome do repositório e construir as requisições para os endpoints oficiais, sem aceitar URLs arbitrárias para download.

RN-013: O download terá limites de tamanho.

RN-014: A extração de arquivos deverá bloquear caminhos que escapem do diretório permitido.

RN-015: Links simbólicos deverão ser ignorados ou tratados sem seguir caminhos externos.

RN-016: O analisador não poderá executar scripts ou comandos contidos no repositório.

RN-017: O número de arquivos, o tamanho individual e o volume total processado terão limites.

RN-018: O processo C++ deverá rodar com permissões restritas, preferencialmente em ambiente isolado e sem acesso à rede.

RN-019: Em caso de falha, a análise será marcada como erro, preservando a disponibilidade do portfólio.

RN-020: O backend deverá encerrar processos que ultrapassarem os limites configurados.

O download e a extração serão responsabilidades do backend e da infraestrutura. O C++ receberá apenas o diretório já preparado e validado.
